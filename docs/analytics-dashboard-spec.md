# Omni2MP3 数据监测与看板方案

状态：前端匿名事件采集已开始接入；PostHog 项目配置和线上看板仍待启用。制定日期：2026-10-20。

## 1. 目标与边界

回答四类问题：有多少人到达并使用网页；多少人完成了至少一首歌、共处理了多少首；失败集中在哪些格式和阶段；用户在哪些操作或性能环节受阻。

当前产品是静态网页，文件选择、解密、转码及 ZIP 打包在浏览器内完成。统计只传匿名、结构化事件，音频内容始终留在本机。看板使用需要登录的分析服务；不要在公开网页中放管理凭证。第一版按当前实际界面统计：选文件/拖入、命名方式、ZIP 下载、播放、编辑、删除及清空。README 提到的文件夹导入和目录保存尚不在当前页面，不为它们制作空图表。

## 2. 统一统计口径

所有图表默认只看 `production` 环境，按北京时间（Asia/Shanghai）显示时间。测试流量和内部使用者要能排除，图表同时标明时间范围与样本数。版本发布日应在趋势图标注。

### 时间筛选：整张看板统一生效

看板顶部放置常驻时间筛选器，默认“近 7 天”。点击预设后，指标卡、趋势图、漏斗、失败原因、按钮点击、耗时分布和明细表同时刷新，不允许部分图表仍显示“累计”。页面标题旁明确展示当前起止时间和时区；用户切换看板页时保留所选时间范围。

| 预设 | 时间范围定义 |
| --- | --- |
| 累计 | 从正式埋点上线后第一条可用事件至当前时刻；上线前无法补出历史数据。 |
| 近 1 年 | 从当前北京时间向前推 12 个日历月，至当前时刻。 |
| 近 3 个月 | 从当前北京时间向前推 3 个日历月，至当前时刻。 |
| 近 30 天 | 当前时刻往前 30 × 24 小时，至当前时刻。 |
| 近 7 天 | 当前时刻往前 7 × 24 小时，至当前时刻。 |
| 近 1 天 | 当前时刻往前 24 小时，至当前时刻。 |
| 今天 / 昨天 | 分别为北京时间今天 00:00 至现在、昨天 00:00 至今天 00:00。 |
| 自定义 | 任意选择开始和结束日期及时间，精确到分钟；开始必须早于结束，结束不得晚于当前时刻。 |

查询区间统一使用“含开始、不含结束”的规则 `[start, end)`，避免相邻时间段重复计数。自定义仅选日期时，结束日期按该日结束处理，例如选 10 月 1 日至 10 月 7 日会覆盖 1 日 00:00 至 8 日 00:00 之前；界面须把转换后的准确起止时间显示出来。滚动预设的“现在”以查询时刻为准，手动刷新或按设定的自动刷新周期更新。

趋势图粒度按跨度自动选择：不超过 2 天按小时、不超过 90 天按天、不超过 2 年按周、更长按月；用户可在可读范围内手动切换。指标卡可选显示“与上一等长时间段相比”的变化值；“累计”没有上一等长时间段，不显示环比。访问转化率仍按所选窗口内进入的访客形成队列，成功需发生在其同一访问会话且在进入后 24 小时内；歌曲成功率则按所选窗口内结束的文件计算。这样无论切换哪个预设，分子与分母都遵守第 2 节下表的口径。

| 指标 | 严格定义 | 注意事项 |
| --- | --- | --- |
| 页面打开次数（PV） | `app_opened` 事件数，每次成功载入应用计一次 | 刷新、重复打开会重复计数；不等于人数。 |
| 访问人数（UV） | 时间范围内 `app_opened` 的不同匿名访客 ID 数 | 是浏览器/设备近似值，清除存储、换设备、拦截统计会影响它；不称“真实用户数”。 |
| 会话数 | 分析工具按约定的会话规则生成的访问会话数 | 在看板注明所采用的会话规则。 |
| 导入人数 | 至少有一次 `files_imported.accepted_count > 0` 的不同匿名访客数 | 只打开文件选择器不算导入。 |
| 成功使用人数 | 时间范围内至少有一条成功 `file_finished` 的不同匿名访客数 | 同一个人转多首只计一人；不声称是其历史上的首次成功。 |
| 访客成功转化率 | 在时间范围内打开应用的匿名访客中，于该次访问会话内至少成功处理一首的访客数 ÷ 访问人数 | 分子必须属于分母；跨午夜的会话按开始日期归属。另看“打开→导入→首次成功”漏斗。 |
| 导入歌曲数 | `files_imported.accepted_count` 的总和 | 每次选择或拖入都计；无效文件另列为拒绝数。 |
| 成功/失败歌曲数 | `file_finished` 中 `status=success/failure` 的事件数 | 每个已接受文件最多且恰好发送一次终态事件；关闭页面前未完成的文件不算失败。 |
| 歌曲处理成功率 | 时间范围内成功结束的歌曲数 ÷ 同期所有已结束歌曲数 | 这是“结束时间”口径；导入数另按导入时间统计，不将两个时间范围的事件直接相减。 |
| 未完成歌曲数 | 在选定时间范围内加入队列的 `file_id` 中，截至查询时没有终态事件的个数 | 按“导入时间”形成文件队列；可再分为仍在处理和超过 30 分钟未结束，不能直接当作失败。 |
| 实际转码歌曲数 | 成功 `file_finished` 且 `output_mode=transcoded` 的事件数 | 已是 MP3 而直接输出的成功文件单列为 `passthrough`，不算实际转码。 |
| ZIP 生成成功率 | `zip_finished.status=success` ÷ 所有 `zip_finished` | 单列点击/请求数；浏览器触发下载不代表用户最终保存了文件。 |
| 平均处理时长 | 成功文件 `process_ms` 的算术平均 | 从实际开始处理到成功，不含排队；另展示中位数和 P90，并分开查看失败文件。 |
| 平均等待时长 | `queue_ms` 的算术平均 | 从文件加入队列到开始处理，用于发现大批量等待。 |

“一次导入”指用户一次选择文件或一次拖放，产生一个 `import_id`；处理中再次添加文件会产生新的 `import_id`，但仍可能共享页面上的处理队列。所有人数指标统一使用同一匿名访客 ID，所有歌曲指标以文件为单位，不在同一张图中混用分母。无样本时显示“—”，不显示 0% 或 100%。

## 3. 事件字典

事件名保持稳定，属性变化使用 `schema_version` 管理。PostHog 事件含 `$insert_id`、事件时间、`app_version`、`environment`、匿名 `distinct_id` 和 `$session_id`；文件事件另带本次随机生成的 `file_id` 和 `import_id`。匿名 ID 不与账号、文件内容或文件名关联。前端关闭自动点击采集和会话录像，仅发送事件字典中的白名单属性。

| 事件 | 触发时机 | 主要属性 |
| --- | --- | --- |
| `app_opened` | 应用完成初始化，一次页面加载一次 | 页面来源渠道、设备类型、浏览器大类、PWA/普通页面 |
| `control_clicked` | 用户主动点击可操作控件 | 稳定的 `control_id`、所在区域；只统计真实可点击状态 |
| `files_imported` | 选文件或拖入完成后，无论是否有可接受文件 | `import_id`、`import_method=picker/drop`、`accepted_count`、`rejected_count` |
| `file_queued` | 每个被接受的文件加入队列 | `file_id`、`import_id`、输入格式、大小区间；与 `files_imported.accepted_count` 对账 |
| `file_started` | 单个文件从队列真正开始处理 | `file_id`、输入格式、大小区间、`queue_ms` |
| `file_finished` | 单个文件成功或失败，一首只发送一次 | `status`、输入格式、输出方式、`process_ms`、`decrypt_ms`、`encoder_load_ms`、`encoder_cold_start`、`encode_ms`、失败阶段、错误代码 |
| `zip_requested` | 点击下载 ZIP 且请求真正开始 | 待打包歌曲数、大小区间、命名方式 |
| `zip_finished` | ZIP 生成并触发浏览器下载，或生成失败 | `status`、`zip_ms`、歌曲数、错误代码 |
| `metadata_edit_finished` | 用户确认编辑后操作结束 | `status=success/failure/unsupported`、错误代码；不传编辑内容 |
| `audio_play_started` | 音频实际开始播放 | 只记录动作，不传歌曲信息 |

`control_clicked.control_id` 首版清单：`file_picker_open`、`zip_download`、`clear_results`、`row_play`、`row_edit`、`row_delete`、`edit_cover_toggle`、`edit_title_toggle`、`edit_artist_toggle`、`edit_album_toggle`、`edit_albumartist_toggle`、`edit_genre_toggle`、`edit_confirm`、`edit_cancel`、`name_policy_change`、`footer_upstream`、`footer_license`。拖放用 `files_imported.import_method=drop`，不伪装成按钮点击。音频播放器的原生播放、暂停可用媒体事件统计，不把浏览器原生控件的每个子按钮当成稳定业务按钮。文件选择器打开后取消可能无法在所有浏览器可靠识别，因此不制作“取消率”。

如果要区分“点击 ZIP 按钮”与“实际开始打包”，前者看 `control_clicked`，后者看 `zip_requested`；若按钮禁用或正在打包，不能产生后者。`zip_finished.status=success` 仅表示网页完成打包并触发下载动作，不表示磁盘保存成功。

## 4. 属性白名单与错误分类

允许用于筛选：日期、渠道/UTM（先过滤参数名和值）、浏览器大类、设备类型、是否 PWA、应用版本、导入方式、文件扩展名白名单、大小区间（如 <5 MB、5–20 MB、20–100 MB、≥100 MB）、输出方式、是否首次加载编码器、错误阶段、错误代码。对未知扩展名统一写 `other`，不上传用户自定义后缀全文。

事件属性禁止包含：音频字节、文件名、歌曲名、歌手/专辑、文件路径、封面、Blob/Object URL、完整 URL 查询参数、原始异常堆栈或异常文本、IP 明文。统计请求仍会在网络层暴露访问者的连接 IP；如不需要地理归因，在 PostHog 项目设置中关闭 IP 数据采集。前端先把错误映射到有限枚举；原始错误仅留在本地控制台或用户界面。

| `error_stage` | 建议 `error_code` | 说明 |
| --- | --- | --- |
| `import` | `unsupported_extension` | 仅计入拒绝文件，不进入歌曲处理失败率。 |
| `decrypt` | `invalid_or_corrupt_file`、`unsupported_variant`、`key_or_decrypt_failed`、`metadata_lookup_failed`、`decrypt_unknown` | 根据解密分支和错误来源映射，不用字符串原样上报。 |
| `encoder_load` | `script_load_failed`、`wasm_download_failed`、`wasm_init_failed` | 区分编码器资源加载问题。 |
| `encode` | `encoder_exit_nonzero`、`empty_output`、`memory_limit`、`encode_unknown` | 可另传有限的数值退出码；不要传 FFmpeg 日志。 |
| `zip` | `zip_build_failed`、`zip_unknown` | 不计入歌曲转换失败率。 |
| `metadata_edit` | `unsupported_output`、`metadata_write_failed` | 编辑失败与转换失败分开。 |
| 任意阶段 | `unknown` | 未归类错误先归入此项，定期检查占比并完善分类。 |

## 5. 看板内容与布局

### A. 总览：每天先看这一页

1. 顶部指标卡：PV、UV、会话数、导入人数、成功使用人数、访客成功转化率、导入歌曲数、成功歌曲数、失败歌曲数、歌曲成功率、未完成歌曲数。
2. 趋势：按天展示 UV、成功使用人数、成功歌曲数、失败歌曲数；可按来源渠道和版本筛选。
3. 使用漏斗：打开页面 → 成功导入至少一首 → 至少一首开始处理 → 至少一首处理成功 → 请求 ZIP → ZIP 生成成功。前四步采用访客口径，ZIP 两步也按同一访客去重。漏斗旁展示各步人数和流失率。
4. “首次成功耗时”：从本次访问 `app_opened` 到首次成功的时长，反映完整体验；与单首歌 `process_ms` 分开展示。

### B. 转换质量

1. 按输入格式、大小区间、浏览器、版本查看导入数、成功数、失败数、成功率；只显示有足够样本的分组，低样本仍可在明细表查看。
2. 区分“直接输出 MP3”和“真正转码成 MP3”；展示两类的歌曲数、成功率与时长。
3. 展示失败原因 Top 10、按日趋势和“格式 × 错误代码”表；点击可下钻到匿名事件明细，但不包含文件名或音乐信息。
4. 展示拒绝文件数及占比，避免把格式不支持误判成转换算法故障。

### C. 性能与稳定性

1. 单首处理总耗时、排队时长、解密时长、编码器加载时长、实际转码时长：平均值、中位数、P90，并按格式/大小/浏览器筛选。
2. 首次转码与后续转码分组，识别 FFmpeg/WASM 首次加载的额外耗时。
3. ZIP 生成耗时与失败率，按打包歌曲数和体量区间观察。
4. 异常峰值：过去 1 小时歌曲失败率、编码器加载失败率、P90 处理时长；同时显示样本数，不因少量事件误报。

### D. 功能使用

1. 每个 `control_id` 的点击次数、点击人数和按日趋势；可以按页面区域排序。
2. 选文件与拖入的使用比例；打开选文件控件 → 实际导入的转化率（只作近似，因为取消事件不可可靠捕获）。
3. 命名方式选择占比、播放/编辑/删除使用人数、ZIP 请求次数与生成成功次数。
4. 来源渠道/UTM → 导入 → 首次成功的漏斗，用来评估分享链接带来的有效使用。

### E. 数据质量与运维

1. 每日接收事件量、按版本/环境分布、匿名事件去重数、未知错误占比。
2. `file_queued`、`file_started`、`file_finished` 的漏斗和超时未完成数量；差额包括关页、离线未上传和仍在处理，不能直接当作失败。同一导入批次的排队事件数应等于 `files_imported.accepted_count`。
3. 可选提醒：过去 1 小时已完成文件 ≥20 首且失败率 >10%，或关键错误较最近 7 天同时间段明显升高；阈值在获得真实基线后调整。
4. 独立可用性检查：定时请求网站首页和 MP3 编码资源，检查页面/资源是否可访问。客户端事件无法发现“脚本根本没有加载成功”的访问，因此网站可用性不能只靠埋点判断。

## 6. 实施优先级

| 阶段 | 建议范围 | 完成标志 |
| --- | --- | --- |
| 第一阶段：能看全局 | 页面打开、导入、逐文件排队/开始/终态、ZIP 请求/终态；总览和转换质量页 | 能准确回答有多少人来、多少人成功、多少首成功/失败、哪些格式失败。 |

| 第三阶段：主动发现 | 可用性检查、异常提醒、来源漏斗、回访趋势 | 无需手动盯看板也能发现明显故障，并判断分享渠道效果。 |

## 7. 实施与启用

前端已开始接入 `src/utils/analytics.ts`：它只向 PostHog 事件采集端发送明确允许的属性；项目令牌或采集地址未配置时，发送函数不做网络请求。当前没有 PostHog 项目凭据，因此不会产生线上统计，也不能在 PostHog 账户中替你创建私有看板。

本地预览可在被 Git 忽略的 `.env.local` 中设置：

```text
VUE_APP_POSTHOG_PROJECT_TOKEN=你的项目令牌
VUE_APP_POSTHOG_HOST=https://us.i.posthog.com
VUE_APP_ANALYTICS_ENV=development
```

正式 GitHub Pages 构建读取仓库的 Actions Variables：`POSTHOG_PROJECT_TOKEN` 和 `POSTHOG_HOST`。工作流会将它们映射为构建变量，并固定设置 `VUE_APP_ANALYTICS_ENV=production`。PostHog 项目令牌用于公开网页采集，会编译进静态文件；不要放个人 API 密钥或项目密钥。采集地址须使用你在 PostHog 项目中显示的区域地址。项目配置后，建议在[项目隐私设置](https://posthog.com/docs/settings/projects#ip-data-capture-configuration)中关闭 IP 数据采集（不需要 GeoIP 时），私有看板在 PostHog 账号中查看；这里不能放查询该账号数据所需的个人密钥。

看板建图顺序：先建「Omni2MP3 总览」，加入 PV/UV、导入及成功人数、歌曲成功率、6 步漏斗和每日成功/失败趋势；再按第 5 节建立转换质量、性能与稳定性、功能使用、数据质量四个分区，并将时间筛选设置为全局筛选。上线后先用自己的测试事件核对事件流，再开放链接给用户；测试事件用 `environment=development`，生产看板过滤 `environment=production`。

## 8. 实施位置与验收

- `src/App.vue`：应用打开事件；记录版本，确保每次载入仅一次。
- `src/component/FileSelector.vue`：导入、拒绝、入队、实际开始处理、解密结果和单文件终态；使用 `performance.now()` 计算耗时，按 `file_id` 保证终态只发送一次。
- `src/utils/mp3.ts`：编码器脚本/WASM 加载耗时与失败分类、实际转码耗时；已是 MP3 时标记 `passthrough`。
