# 音乐批量解锁

一个可自托管的批量音乐解锁网页。它基于 [Unlock Music](https://git.unlock-music.dev/um/web) 的浏览器端解密算法，补齐了真正可用的批量工作流：多选、文件夹导入、连续队列、状态追踪、ZIP 下载和目录写入。

文件不会上传到服务器。选择、解密、元数据处理和打包均在浏览器本地完成。

## 在线使用

[打开音乐批量解锁网页](https://magiicccc.github.io/music-batch-unlock/)

每次推送到 `main` 分支时，GitHub Actions 会先运行测试和生产构建，再自动更新 GitHub Pages。

## 批量能力

- 同时选择多个音乐文件。
- 选择整个文件夹，自动忽略不支持的文件。
- 拖入多个文件并持续追加批次。
- HTTPS 部署时最多使用 4 个 Web Worker，避免无限并发耗尽内存。
- 本地或 Worker 不可用时使用可靠的单线程队列，完整处理所有项目。
- 将全部结果生成为一个 ZIP，重名文件自动添加序号。
- 在 Chrome、Edge 等支持 File System Access API 的浏览器中直接写入指定目录。
- 保留标题、歌手、专辑和封面，并支持在下载前修改 MP3 / FLAC 元数据。
- 支持 PWA 离线使用；配置统计项目后会发送匿名功能使用事件，音频文件和歌曲信息不会上传。

## 支持格式

- 网易云音乐：`.ncm`、`.uc`
- QQ 音乐：`.qmc0`、`.qmc2`、`.qmc3`、`.qmcflac`、`.qmcogg`、`.mflac`、`.mgg` 等
- 酷狗音乐：`.kgm`、`.kgma`、`.vpr`
- 酷我音乐：`.kwm`
- 虾米音乐：`.xm`
- 喜马拉雅：`.x2m`、`.x3m`
- 咪咕音乐：`.mg3d`
- 普通音频：`.mp3`、`.flac`、`.ogg`、`.m4a`、`.wav`

JOOX `.ofl_en` 支持未包含在本分支，因为上游解密包只发布在当前无法公开访问的私有 npm 源。其他格式均使用公共 npm 依赖即可构建。

## 本地开发

环境要求：Node.js 22 或 24、npm。

```powershell
npm ci
npm run serve
```

浏览器打开终端显示的本地地址。开发模式使用单线程队列，生产构建在 HTTP(S) 下启用 Worker。

## 测试与构建

```powershell
npm test -- --runInBand
npm run build
```

生产静态文件位于 `dist/`。可将整个目录部署到 GitHub Pages、Cloudflare Pages、Vercel、Netlify、Nginx 或任意静态文件服务。为了启用 PWA、Web Worker 和目录写入，请使用 HTTPS；直接双击 `index.html` 时浏览器能力会受限。

## 使用流程

1. 点击“选择多个文件”或“选择整个文件夹”，也可以拖入多个文件。
2. 等待本批进度达到完成。成功和失败文件会分别计数。
3. 检查标题、歌手、专辑和封面，必要时编辑元数据。
4. 点击“下载 ZIP”一次性下载，或点击“保存到文件夹”直接写入磁盘。

ZIP 采用 STORE 模式：MP3、FLAC 等音频本身已经压缩，再压缩不会明显减小体积，反而会增加等待时间和内存占用。

## 关键改动

- 修复上游 `DecryptQueue` 在第一项完成后没有调用下一次 `consume()` 的问题。
- 用原生多文件和 `webkitdirectory` 输入替代不明确的单一上传入口。
- 增加逐项状态、总进度、拒绝文件汇总和并发上限。
- 增加 ZIP 打包、重名处理、跨平台文件名清理和目录批量写入。
- 移除在线版本检查；统计事件仅在配置分析项目后启用，并严格限制上报字段。
- 修复编辑元数据时在声明前使用 `mime` 的运行时错误。

## 隐私模型

本项目是纯静态前端，不包含音频上传接口。解密、转码和打包均在浏览器本地完成。配置 PostHog 项目后，网页会发送匿名事件用于统计访问、按钮使用、转换结果、耗时和错误类别；事件不包含音频、文件名、歌曲名、歌手、专辑或路径。统计请求在网络层会向分析服务暴露连接 IP；如不需要基于 IP 的地理属性，应在 PostHog 项目设置中关闭 IP 数据采集。未配置统计项目时不会发送这些统计事件。NCM 封面补全等个别上游算法可能根据文件内元数据请求公开图片地址；音乐音频内容不会发送出去。如需完全离线，可在首次加载后断网使用 PWA，或审查并关闭相应封面请求。
